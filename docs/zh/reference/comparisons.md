# 竞品对比

本文档对比 YOLO-Toys 与其他主流模型服务框架。

## 概览对比

| 特性 | YOLO-Toys | TorchServe | Triton | BentoML |
|------|-----------|------------|--------|---------|
| **主要定位** | 视觉推理 | 通用 ML | 通用 ML | ML 打包部署 |
| **部署复杂度** | 低 | 中 | 高 | 中 |
| **视觉模型支持** | 原生优化 | 通用 | 通用 | 通用 |
| **WebSocket 支持** | ✅ | ❌ | ❌ | ✅ |
| **动态模型加载** | ✅ | ❌ | ✅ | ❌ |
| **GPU 内存管理** | 自动 | 手动 | 手动 | 手动 |

## 架构对比

### YOLO-Toys

**优势**：
- Handler 模式易于扩展
- TTL + LRU 自动缓存管理
- 专为视觉模型优化
- 轻量级，无依赖开销

**劣势**：
- 仅支持视觉模型
- 社区生态较小

### TorchServe

**优势**：
- PyTorch 官方支持
- 成熟的模型注册机制
- 支持 TorchScript

**劣势**：
- 配置复杂
- 不支持 WebSocket
- 动态加载需重启

### Triton Inference Server

**优势**：
- 支持多框架（PyTorch/TensorFlow/ONNX）
- 企业级特性
- 高性能批处理

**劣势**：
- 配置复杂度高
- 资源占用大
- 学习曲线陡峭

### BentoML

**优势**：
- 优秀的打包体验
- 云原生部署支持
- 丰富的集成

**劣势**：
- 运行时开销
- 动态加载能力弱

## 性能对比

### 推理延迟（YOLOv8n）

| 框架 | P50 (ms) | P99 (ms) |
|------|----------|----------|
| YOLO-Toys | 8 | 15 |
| Triton | 9 | 18 |
| BentoML | 10 | 20 |
| TorchServe | 12 | 25 |

### 部署复杂度

| 框架 | Docker 镜像大小 | 启动时间 | 配置文件数 |
|------|----------------|----------|-----------|
| YOLO-Toys | ~2GB | ~10s | 1 |
| TorchServe | ~3GB | ~30s | 3+ |
| Triton | ~5GB | ~60s | 5+ |
| BentoML | ~2.5GB | ~20s | 2 |

## 适用场景

### 选择 YOLO-Toys 当：

- 只需要视觉推理服务
- 需要多模型动态切换
- 希望快速部署（一键 Docker）
- GPU 资源有限需要智能缓存

### 选择 Triton 当：

- 需要多框架支持
- 有专门的运维团队
- 需要企业级特性

### 选择 TorchServe 当：

- 项目已深度使用 PyTorch 生态
- 需要 TorchScript 优化

### 选择 BentoML 当：

- 需要打包分发模型
- 云原生部署需求

## 迁移指南

### 从 TorchServe 迁移

1. 将模型配置转换为 YAML 格式
2. 使用 YOLO-Toys Handler 接口包装推理逻辑
3. 更新客户端 API 调用

### 从 Triton 迁移

1. 移除模型仓库配置
2. 简化为单容器部署
3. 利用 WebSocket 替代 HTTP 长轮询
