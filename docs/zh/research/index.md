# 研究

研究章节把 YOLO-Toys 从"一个能跑的仓库"提升为"一个值得研究的系统样本"。这里汇集了项目所依赖的论文脉络、相关开源系统对照，以及帮助高级读者建立判断的背景材料。

## 研究面向

| 页面 | 价值 |
| --- | --- |
| [参考文献](/zh/citations) | 支撑模型家族与底层框架的文献与引用入口 |
| [竞品对比](/zh/reference/comparisons) | 与 Triton、TorchServe、BentoML、自建 FastAPI 方案的取舍比较 |
| [演进思考](/zh/research/evolution) | 架构演进史：从扁平端点到 Handler 边界，从朴素缓存到运营感知 |
| [架构图谱](/zh/architecture/) | 运行时系统结构与执行路径说明 |
| [学院](/zh/academy/) | 面向模式、权衡与扩展边界的长文分析 |

## 为什么单独设置这一章

很多模型服务仓库只讲"怎么跑起来"，却不解释"为什么这样组织"。YOLO-Toys 的价值之一，就是把异构视觉模型统一到一套服务边界时，如何保持可理解、可扩展、可比较。

研究章节增加了两个大多数项目缺失的内容：

1. **演进叙事**：架构如何一步步走到今天，包括那些被舍弃的死胡同
2. **学术根基**：BibTeX 条目、设计模式引用，以及与工业级 serving 系统的对照分析

## 推荐阅读路径

1. 先读 [架构图谱](/zh/architecture/) 把系统骨架建立起来
2. 再读 [竞品对比](/zh/reference/comparisons) 找到项目所处位置
3. 读 [演进思考](/zh/research/evolution) 理解每个边界背后的历史推理
4. 需要追溯上游背景时查阅 [参考文献](/zh/citations)
5. 最后进入 [学院](/zh/academy/) 看模式级别的深入分析
